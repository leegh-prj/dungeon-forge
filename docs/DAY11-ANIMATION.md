# Day 11 — 전투 스프라이트와 스테이지 패턴

## 실제 적용한 리소스
`assets/sprites/` 아래 독립 SVG 스프라이트 **18프레임**:
- 영웅: 대기 2, 공격 3, 방어 2, 피격 1 (8)
- 왕관 슬라임: 대기 2, 공격 2, 피격 1 (5)
- 마그마 슬라임: 대기 2, 공격 2, 피격 1 (5)

각 프레임은 텍스트/SVG로 구현한 **별도 그림 리소스**이며, 시간·전투 이벤트에 따라 `img.src`를 교체한다. 단순 CSS 요소 흔들기만 사용하는 방식과 다르게 포즈 변화가 포함된다.

## 적용 방식
- 대기 프레임은 2프레임 순환.
- 일반 공격과 강타에서 영웅 공격 3프레임, 피격 적 1프레임 교체.
- 방어 스킬에서 별도 방패 포즈 2프레임.
- 적 공격 직전/실행 시 공격 포즈 2프레임.
- 피격 때 영웅 피격 포즈.
- JS 기반 프레임 전환 최소 간격 약 115ms, 실제 브라우저 렌더링 프레임레이트와 별도.

## 보스 전투
- 보스 공격 패턴 3종: 용암 내려찍기, 화염 충격파, 연속 할퀴기
- 공격까지 남은 시간 표시 및 임박 경고.
- 순차 패턴별 공격력 조정. 화염 충격파 후 회복 효과(현재 임시 밸런스).
- 수동/자동 공격 및 방어 조작 유지.

## 스테이지와 보상
- 4회 처치 루프의 진행 단계 점 표시.
- 보스 격파 후 다음 스테이지 이동, 마력 결정 +5, 광석 +35 추가.
- 단계 완료 메시지 및 보상 확인 카드.

## 검증
GitHub의 5개 대표 프레임 재열람 성공. JavaScript 문법 검사 통과, 모의 DOM 기반 전투 스모크 테스트(경로, 캐릭터 DOM, 자동/수동 조작, 스테이지 상승, 보스 보너스) 통과.

## 한계
이번 리소스는 **실행 가능한 독립 SVG 게임 스프라이트**지만, 고해상도 승인 원화(WebP)를 컷아웃한 애니메이션 시트는 아니다. 제작 콘셉트와 보다 밀접한 투명 PNG/WebP 분리 및 정밀 프레임 작업은 추가 아트 작업이 필요하다. 실제 휴대폰/브라우저 QA 및 애니메이션 디테일 검증은 아직 완료되지 않았다.
