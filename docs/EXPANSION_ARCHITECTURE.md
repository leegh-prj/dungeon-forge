# 던전 대장간 — 확장 개발 설계 v1.0

- 작성: 2026-10-13
- 상태: **장기 확장 요구사항 승인 / 세부 수치 가설**
- 기본 원칙: 제작 60% + 전투 40%, 그래픽 우선 개발, 비로그인 싱글플레이로 시작
- 선행 문서: [UI_STYLE_GUIDE.md](UI_STYLE_GUIDE.md)

## 1. 범위와 우선순위

| 구분 | 지금 | 이후 | 장기 |
|---|---|---|---|
| 아트 | 치비 영웅/적/장비/배경 실그래픽 적용 | 전투/제작 애니메이션 | 속성별 독립 지역 아트 |
| 플레이 | 자동 탐험 + 방어 타이밍 + 장비 제작 | 속성/제작 시너지 | 시즌 콘텐츠 |
| 계정 | 로컬 저장 | 여러 로컬 프로필 | 선택적 로그인/클라우드 동기화 |
| 외형 | 고정 주인공, 분리 가능한 렌더 계층 | 피부·얼굴·머리·색상 | 체형·의상·세부 슬라이더 |
| 지역 | 물/불을 우선 프로토타입 | 번개/독/대지 | 로봇/얼음/빛/어둠 등 |

로그인, 캐릭터 편집 UI, 대규모 스테이지는 **현재 구현하지 않는다**. 데이터 형식만 먼저 설계한다.

## 2. 프로필 및 캐릭터 커스터마이징

### 2.1 저장 데이터 (스키마 1)
```json
{
  "schemaVersion": 1,
  "profileId": "local-uuid",
  "auth": { "provider": "guest", "remoteUserId": null },
  "appearance": {
    "genderPresentation": "masculine",
    "skinToneId": "skin_01",
    "faceId": "face_01",
    "hairStyleId": "hair_short_01",
    "hairLengthId": "short",
    "hairColorId": "brown_01",
    "bodyTypeId": "standard",
    "eyeStyleId": "eyes_01"
  },
  "progress": {
    "stageId": "water_001",
    "resources": { "gold": 60, "ore": 20, "crystal": 5 },
    "inventory": [],
    "equipment": {},
    "discovery": []
  },
  "updatedAt": "ISO-8601"
}
```

- 성별 표현은 의상·외모 선택과 분리한다. 모든 피부톤/헤어/얼굴 옵션을 제한 없이 혼합 가능하도록 한다.
- 색상 선택은 팔레트/마스크 레이어; 머리 길이·스타일은 스프라이트 ID.
- 체형 변경은 실루엣·장착 장비와 맞물려 아트 작업량이 크므로 후순위.
- 런타임 레이어: base body → face → hair back → armor → hair front → weapon/shield → FX.
- 저장은 UUID로 로컬 프로필을 식별하고, 이후 로그인 계정과 매핑하는 방식. **로그인 필수화하지 않음.**
- 이전 저장 데이터 마이그레이션, 프로필 내보내기/가져오기, 다중 기기 충돌 해결 정책을 준비한다.

### 2.2 계정 연동 원칙
1. Guest 프로필 생성 → 로컬 자동 저장
2. 선택적 계정 로그인 시 원격 계정에 연결
3. 충돌 발생 시 로컬·원격 진행도와 갱신 시각을 사용자에게 표시
4. 아이템 식별자는 UUID로 관리, 중복/복제 처리 정책 명시
5. 민감 데이터 최소화, 제3자 인증 토큰을 게임 저장 파일에 평문 저장하지 않음

## 3. 속성 시스템

각 스테이지·몬스터·재료·장비는 `elementId`를 공유한다.

| ID | 속성 | 지역 콘셉트 | 핵심 위협 | 방어 전략 | 대표 제작재료 |
|---|---|---|---|---|---|
| water | 물 | 가라앉은 수로 | 둔화/물보라 | 막기·냉기 저항 | 물의 결정 |
| fire | 불 | 용암 용광로 | 화상/폭발 | 화상 저항/보호막 | 화염석 |
| lightning | 번개 | 폭풍 탑 | 연쇄 감전 | 절연 갑옷/차단 | 전류 코어 |
| poison | 독 | 부식 늪지 | 지속 피해 | 정화/재생 | 독낭 |
| earth | 대지 | 거암 신전 | 강한 일격 | 고방어/반격 | 거암 파편 |
| robot | 로봇/기계 | 기계 유적 | 방어 관통/패턴 | 실드 교대/회로 방해 | 동력 코어 |
| ice | 얼음 | 얼어붙은 동굴 | 빙결 | 제어 저항 | 빙결석 |

- 기계/로봇은 자연 원소가 아니라 **테마·세력 태그**로 분리 가능한 구조를 권장한다.
- 속성 상성 배율은 검증 전 가설. 상성만으로 장비 선택이 강제되지 않도록 한다.
- 방어의 가치는 방어력뿐 아니라 방패 반격, 속성 저항, 보호막, 피해 감소 및 스킬 타이밍으로 구성한다.

## 4. 스테이지·몬스터 데이터

```json
{
  "stageId": "fire_001",
  "biomeId": "volcanic_forge",
  "elementId": "fire",
  "level": 1,
  "waves": [
    { "monsterId": "fire_slime", "count": 4 },
    { "monsterId": "magma_golem_boss", "count": 1, "boss": true }
  ],
  "rewardTableId": "fire_easy",
  "artSetId": "forge_fire_01"
}
```

```json
{
  "monsterId": "magma_golem_boss",
  "elementId": "fire",
  "tags": ["boss", "golem"],
  "hp": 1200,
  "attack": 75,
  "defense": 25,
  "attackPatternId": "magma_telegraph_v1",
  "dropTableId": "magma_boss_01",
  "spriteSetId": "magma_golem_v1"
}
```

**구분:** 속성 / 지형 / 전투 패턴 / 드롭 테이블 / 비주얼을 독립 데이터로 둔다. 확장 시 코드 수정 없이 신규 콘텐츠를 추가하는 것이 목표.

## 5. 제작·재료·장비 시스템

### 5.1 제작 흐름
탐험 보상 → 재료 선택 → 무기/갑옷/방패/반지 선택 → 집중(균형/공격/방어) → 레시피 확인 → 제작 → 등급/옵션 공개 → 장착/분해/도감.

### 5.2 장비 데이터
```json
{
  "itemId": "uuid",
  "blueprintId": "guardian_shield",
  "slot": "shield",
  "rarityId": "rare",
  "elementId": "water",
  "affixIds": ["guard_window_plus", "water_resist"],
  "stats": { "attack": 0, "defense": 32, "hp": 25 },
  "level": 1,
  "craftedAt": "ISO-8601"
}
```

- 등급: 일반 / 고급 / 희귀 / 영웅 / 전설 (신화는 확장 시 검토).
- 제작식은 재료 ID와 확률표·효과 풀로 관리. 확률과 재료 소모를 항상 유저에게 표시한다.
- 장비 별 고유 행동 변화가 우선: 화상 연쇄, 흡혈, 방패 반격, 보호막, 정화 등.
- 공격 특화 장비가 보스전에서 압도하지 않도록 방어 관통/피해 감소/패턴별 대응을 설계한다.
- 제작 실패로 필수 재화를 전부 잃는 형태는 초기에는 피한다.

## 6. 아트 리소스 구조

```
assets/
  art/characters/hero/{base,face,hair,equipment,actions}/
  art/npc/blacksmith/
  art/monsters/{water,fire,lightning,poison,earth,robot}/
  art/equipment/{weapon,armor,shield,ring}/
  art/environments/{dungeon,forge}/
  art/ui/{frame,button,rarity,icons}/
  references/   # 합성 콘셉트 시트 (원본 참조용)
```

- **주의:** 생성된 합성 아트보드 전체는 투명 스프라이트가 아니다. 자동 크롭된 소재는 포스터의 문구·배경이 남을 수 있다.
- 실제 게임 리소스로 사용하기 전 각 이미지의 크롭 경계, 가장자리, 투명도, 해상도를 검사한다.
- 캐릭터 애니메이션이 필요하면 Idle / Attack / Guard / Hit / Win 상태별 동일 캐릭터 유지가 필수.
- 고화질 UI 배경과 실제 클릭 요소는 별도 관리. 포스터 속 글자를 클릭 가능한 버튼으로 사용하지 않는다.

## 7. 구현 순서 및 수용 기준

1. **그래픽:** 웹판 4개 화면에 실제 캐릭터/적/NPC/장비 아트 적용. 이모지 의존도 줄이기.
2. **저장:** 로컬 세이브 버전 관리 및 외형 기본 프로필 데이터 준비.
3. **데이터:** 속성/지역/몬스터/재료/제작 정의 JSON 분리.
4. **전투:** 속성 저항 + 방패 타이밍 + 방어구의 특수 효과.
5. **제작:** 재료 선택이 실제 결과에 영향을 주는 시스템 구현.
6. **검증:** 모바일 터치, 저장/복원, 원정/보스 진입, 재화 수급, 360px 화면.

## 8. 품질 게이트
- 모바일 첫 실행 10초 이내 게임 진입을 목표.
- 다른 스테이지/속성 추가가 하드코딩을 늘리지 않는지 확인.
- 브라우저 콘솔 오류 없음; 저장 데이터 손상 시 안전 초기화; 탭 전환 중 버튼 클릭 문제 없음.
- 새 아트 적용 뒤 눈에 띄는 화질 저하/텍스트 포함 크롭/과도한 이미지 다운로드가 없어야 한다.
- 실제 Android/iOS에서의 성능은 별도 테스트가 필요하다.

## 9. 보류된 의사결정
- 나중의 로그인 공급자, 계정 동기화 서버, 유료 상품
- 체형별 장비 스프라이트 제작 범위
- 속성 상성 상세표 및 희귀도 확률 재설계
- 글로벌 출시 로컬라이징, 운영 이벤트 빈도
